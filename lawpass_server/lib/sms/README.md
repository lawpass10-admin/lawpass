# lib/sms — שליחת קמפיין SMS

שליחת הודעת SMS אחת לרשימת מספרי נייד ישראליים (עד ~500 בהרצה), דרך
[SMS4Free](https://www.sms4free.co.il). נטען מקובץ CSV/Excel, מוגדר מקובץ JSON
אחד, ורץ כסקריפט מהשרת — אין לזה endpoint ב-API.

```
lib/sms/
  campaign.json           ← כאן עורכים את טקסט ההודעה ואת שם השולח
  recipients.csv          ← כאן שמים את רשימת המספרים (לא נכנס ל-git)
  recipients.example.csv  הדוגמה שכן נשמרת ב-git
  phone.js                נרמול מספר נייד ישראלי (המקום היחיד)
  provider.js             הדרייבר של SMS4Free + חישוב עלות בסגמנטים
  recipients.js           קריאת CSV / Excel → רשימה נקייה וללא כפילויות
  campaign.js             ההרצה עצמה: תכנון, שליחה, יומן
  logs/<campaignId>.jsonl יומן השליחות (לא נכנס ל-git)
```

הסקריפט: `../../scripts/send-sms-campaign.js`

---

## שלב 1 — הגדרת החשבון (פעם אחת)

ב-`app/.env.local`:

```
SMS_PROVIDER=sms4free
SMS4FREE_KEY=...
SMS4FREE_USER=...
SMS4FREE_PASSWORD=...
```

כל עוד `SMS_PROVIDER=mock` (ברירת המחדל) — שום הודעה לא יוצאת, גם עם `--send`.
זה בכוונה: סביבה מוגדרת־למחצה צריכה להגיע לאף אחד, לא לחמש מאות אנשים.

### על שם השולח "LawPass"

`campaign.json` מגדיר `"sender": "LawPass"`, כדי שהנמען יראה מיד ממי ההודעה.

**אבל** — שם שולח באותיות הוא לא משהו שעובד ברגע שקונים חבילה. בישראל הוא
דורש חבילה בתשלום **וגם** רישום מראש של השם מול המפעילים הסלולריים, וזה לוקח
כמה ימים. עד שזה מאושר, SMS4Free יקבל כשולח רק את מספר הטלפון שאיתו נרשמתם,
וידחה כל דבר אחר עם שגיאה `-2` (הסקריפט מתרגם אותה להודעה בעברית).

לכן גוף ההודעה פותח במילה **LawPass** ולא מסתמך רק על הכותרת: גם אם ההודעה
מגיעה ממספר טלפון, ברור ממי היא.

## שלב 2 — רשימת הנמענים

שימו קובץ בשם `recipients.csv` בתיקייה הזו. עמודה אחת של מספרי נייד:

```
phone
0541234567
054-765-4321
+972521112233
```

- **פורמט:** `.csv`, `.txt`, או `.xlsx`/`.xls`.
  לאקסל צריך `npm install xlsx` בתיקיית `lawpass_server`; הדרך הפשוטה יותר היא
  פשוט "שמירה בשם → CSV" מתוך אקסל.
- **לא צריך להגדיר איזו עמודה:** אם יש בקובץ גם שמות, הקורא לוקח מכל שורה את
  התא הראשון שהוא מספר נייד ישראלי תקין. שם לא יכול להתפרש כמספר.
- **שורת כותרת** מזוהה ומדולגת לבד.
- **נייד בלבד** (05X). קו נייח נדחה בקול — שורה שתחויב ולעולם לא תיקרא.
- **אקסל אוכל את האפס המוביל** (`541234567`). זה מטופל.
- **כפילויות** נספרות ונשלחות פעם אחת.

הקובץ עצמו **לא נכנס ל-git** (ראו `.gitignore` בתיקייה) — זו רשימה של מספרי
טלפון של אנשים אמיתיים.

## שלב 3 — טקסט ההודעה

`campaign.json`:

| שדה | מה זה |
|---|---|
| `campaignId` | שם הקמפיין. **קובע את שם קובץ היומן** — החליפו אותו בכל קמפיין חדש, אחרת הקמפיין החדש "ידלג" על כל מי שקיבל את הקודם. אותיות/ספרות/מקף בלבד. |
| `sender` | שם השולח. ראו האזהרה למעלה. |
| `message` | **גוף ההודעה.** זה מה שעורכים. `\n` = שורה חדשה. |
| `optOutLine` | שורת ההסרה, מתווספת אוטומטית בסוף. |
| `recipientsFile` | שם קובץ הנמענים. ברירת מחדל `recipients.csv`. |
| `maxPerRun` | תקרת נמענים להרצה אחת. ברירת מחדל 500. |
| `concurrency` | כמה שליחות במקביל. 4 ≈ 500 הודעות בדקה. |
| `pauseMs` | השהיה בין שליחות, במילישניות. |

### עברית עולה כפול

סגמנט אחד באנגלית = 160 תווים. **בעברית = 70 תווים** (ו-67 כשההודעה
מתפצלת). הודעה של 100 תווים בעברית היא שתי הודעות בחשבון, לא אחת.

הסקריפט מדפיס את זה לפני כל שליחה — `segments` ו-`total cost`. 500 נמענים ×
2 סגמנטים = 1,000 הודעות בחבילה. זה המספר שלפיו קונים.

## שלב 4 — הרצה

מתוך `lawpass_server/`:

```bash
# תצוגה מקדימה — קורא את הקובץ, בונה את ההודעה, מתמחר. שולח כלום.
npm run sms:campaign

# בדיקה חיה למספר אחד (לא נוגע ברשימה ולא ביומן הקמפיין)
node scripts/send-sms-campaign.js --to 0541234567 --send

# הקמפיין עצמו
node scripts/send-sms-campaign.js --send
```

| דגל | מה הוא עושה |
|---|---|
| `--send` | שולח באמת. בלעדיו — תצוגה מקדימה בלבד. |
| `--to <מספר>` | למספר אחד בלבד, מתעלם מהקובץ. |
| `--file <נתיב>` | קובץ נמענים אחר להרצה הזו. |
| `--config <נתיב>` | `campaign.json` אחר להרצה הזו. |
| `--limit <n>` | תקרה נמוכה יותר מ-`maxPerRun` — להרצה ראשונה זהירה. |
| `--resend` | מתעלם מהיומן ושולח שוב לכולם. |
| `--yes` | מדלג על האישור המוקלד. |

### האישור לפני שליחה

האישור מתאים את עצמו לגודל ההרצה:

- **עד 5 נמענים** — `y/N` רגיל. זו הרצת בדיקה; אפשר לראות את כל המספרים על
  המסך, וטעות מגיעה למישהו שאפשר להתקשר אליו ולהתנצל.
- **מעל 5** — צריך **להקליד את מספר הנמענים**. עד הבדיקה השלישית כבר לא קוראים
  שאלת `y/N`, והרפלקס הזה עדיין שם בהרצה שמגיעה ל-500 איש. אם התכוונתם לשלוח
  לאחד והמסך אומר 437 — הקלדת `1` תיכשל ושום דבר לא ייצא.

`--yes` מדלג על האישור לגמרי (להרצה לא מפוקחת).

כל המספרים על המסך ממוסכים (`054-***-4567`), כך שאפשר להעתיק תצוגה מקדימה
לצ'אט בלי להעתיק איתה את הרשימה.

## היומן, והרצה חוזרת

כל תוצאה נרשמת מיד ל-`logs/<campaignId>.jsonl`, שורה לנמען.

**הרצה חוזרת מדלגת על כל מי שכבר נשלח אליו בהצלחה.** זה מה שהופך את הסקריפט
לבטוח להרצה חוזרת — והוא *יורץ* שוב: מחשב נרדם, אינטרנט נופל, מישהו סוגר
טרמינל ב-300 מתוך 500. בלי היומן, ההתאוששות היא או לשלוח ל-300 אנשים פעמיים
או לערוך CSV ביד.

**כישלון לא נחשב "נשלח"** ויקבל ניסיון נוסף בהרצה הבאה — בכוונה, כי כישלון
בודד הוא לרוב תקלה רגעית.

מעל `maxPerRun`? הסקריפט שולח 500, אומר כמה נשארו, ואפשר פשוט להריץ שוב.

## לפני שליחה לרשימה אמיתית — חוק הספאם

הודעת שיווק ב-SMS היא **דבר פרסומת** לפי תיקון 40 לחוק התקשורת. המשמעות:

1. **צריך הסכמה מראש** של הנמען לקבל פרסומת. רשימת מספרים שנקנתה או נאספה
   ממקור אחר אינה הסכמה.
2. **חייבת להיות דרך להסיר את עצמך** — `optOutLine` נוסף אוטומטית, אבל מישהו
   צריך גם *לקרוא* את תשובות ה"הסר" ולהוציא אותם מהרשימה הבאה.
3. **הפיצוי הוא לפי הודעה** — עד 1,000 ₪ לכל הודעה, ללא הוכחת נזק. 500
   הודעות הן החשיפה היקרה.

הקוד לא יכול לענות על שאלת ההסכמה. זו שאלה שצריך לענות עליה לפני ההרצה
הראשונה, לא אחריה.
